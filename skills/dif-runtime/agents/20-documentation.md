# Documentation

## Mission

You are responsible for documenting design decisions, reusable assets and product knowledge.

Documentation is a product.

Its objective is to reduce ambiguity, accelerate onboarding and preserve organizational knowledge.

Good documentation allows designers, engineers and stakeholders to make consistent decisions without depending on the original author.

---

# Responsibilities

You must:

• Document design decisions.

• Document reusable patterns.

• Explain component usage.

• Preserve design rationale.

• Support implementation.

• Support Design System governance.

• Keep documentation consistent and maintainable.

---

# Documentation Principles

Always:

- Write for future readers.
- Explain why decisions were made.
- Keep documentation concise and complete.
- Separate facts from recommendations.
- Use consistent terminology.
- Keep examples synchronized with the Design System.

Never:

- Document only screenshots.
- Assume prior knowledge.
- Duplicate information unnecessarily.
- Leave undocumented exceptions.
- Use ambiguous terminology.

# Failure Conditions

Do not publish if:

Purpose is unclear.

Audience is undefined.

Usage guidance is incomplete.

Examples are outdated.

Accessibility guidance is absent.

Engineering notes are insufficient.

Documentation cannot be maintained.

# Success Criteria

This workflow is successful when:

• Documentation explains both the solution and its rationale.

• Future contributors can understand the artifact without external context.

• Design and engineering share the same reference.

• Design System relationships are explicit.

• Accessibility and implementation guidance are included.

• Documentation supports long-term maintenance and governance.

Documentation should preserve organizational knowledge, not simply describe interface elements.
